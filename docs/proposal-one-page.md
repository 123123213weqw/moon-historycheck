# HistoryCheck 项目申报参考书

## 并发历史线性一致性验证与反例证据

GitHub 账号：123123213weqw。仓库：https://github.com/123123213weqw/moon-historycheck 。模块：123123213weqw/moon_historycheck@0.1.0。主要语言 MoonBit，Apache-2.0。用户指定用于替换原 PolicyForge 申报；本文供个人参考。

**项目目标。** 面向并发组件和存储服务测试，检查给定调用返回历史是否存在符合顺序规范、保留实时先后关系的串行解释。已实现寄存器／CAS、独立键值寄存器、FIFO 队列、LIFO 栈、互斥锁、成员集合和整数计数器模型，并提供机器可读判定与可复现输入输出。

**核心实现。** 前驱约束下的有界搜索以已选集合和完整模型状态记忆化，候选按最早返回序号优先探索；独立见证验证器重算覆盖、先后关系和模型输出。分区只适用于明确独立的键模型，合并后再验证全局顺序。失败历史按块删除反复求解缩减，最终以单操作粒度确认最小性，未知不支持删除或最小性结论。

**负面证据。** 独立广度闭包搜索与证书验证入口检查每个合法启用分支、后继状态、初始绑定和可达性；缺失分支或篡改会被拒绝。证据限于具体历史和内置模型，不是对实现本身的形式化证明。

**验证。** 31 项手写与 80 项生成测试，共 111 项声明；80 组夹具也经过 CLI。独立参考覆盖 840 份历史、120 次分区、20 次缩减；另有 210 份闭包对照，包含 93 份负证书和 117 份成功见证。规模覆盖 256 操作、100 键／200 操作及高重叠预算未知。异步记录示例分别产生正确和受控陈旧读历史。公共 CI 与公共包安装记录另附。

**规模与边界。** 自有生产有效代码 1,551 行，其中领域实现 1,313 行，排除依赖、测试、生成内容及文档。历史默认最多 256 操作（可提高到 4096），预算耗尽或未完成操作返回未知；不支持事务、任意用户模型或跨机未校准时间推断。仅证明有限观测的结论，不证明系统全部执行正确。

新仓库没有沿用其他项目提交和测试数量。参考 Porcupine 等公开工作，来源和 AI 辅助已披露；实际报名替换和最终审核状态以回执及组委会确认为准。
